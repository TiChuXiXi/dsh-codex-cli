## 统一视觉规范

合并方向基础：#fcfcfa 内容面、#f4f4f1 辅助面、#dfe1e0 分隔、#2c323a 主文字、#606b77 次文字、#55637a 蓝灰强调；深色对应 #222428 内容面、#1c1e22 辅助面、#e4e6ea 主文字、#b0bdd0 强调。颜色通过语义变量引用，组件内部不散落独立色值。

主题切换增加圆形扩散：参考 https://gw.thinktop.com.cn/ 的实际效果，从按钮点击位置向外覆盖，浅转深、深转浅均为 460ms，缓动 cubic-bezier(.4, 0, .2, 1)。合并初稿已实现。使用 View Transition 新主题快照做圆形裁剪，暂时关闭控件颜色过渡，避免边界内出现半切换颜色。键盘触发时以按钮中心为原点；减少动态效果或不支持 API 时直接切换；连续点击期间只保留一个动画；动画后仍记住主题。正式插件迁移时限定视觉作用范围，避免让 DSH 外壳一起切换。

间距使用 4/8/12/16/24/32；常规控件圆角 6–8px，输入卡片 12px，弹窗 12px。阴影用于浮层，不给每个内容区叠加阴影。普通中文用系统无衬线字体，代码和路径用等宽字体。

图标选择 [Lucide 官方 React 包](https://lucide.dev/packages)，按名称导入；初稿已使用同源原始 SVG，并保留 许可证（设计稿已移除）。16px 用于紧凑标签，18px 用于常规操作，20px 用于突出入口；统一 strokeWidth 1.75、currentColor、装饰 SVG aria-hidden。可点击区域优先 44×44，不能仅靠颜色表达状态。

| 用途 | Lucide 名称 |
| --- | --- |
| 新建、关闭、更多 | Plus / X / Ellipsis |
| 展开、折叠、路径 | ChevronRight / ChevronDown / ChevronLeft |
| 文件、目录、文档 | FileCode / FileText / Folder / FolderOpen |
| 右栏、分栏、全屏 | PanelRight / Columns2 / Maximize2 / Minimize2 |
| Git、终端、浏览器 | GitBranch / GitPullRequest / Terminal / Globe |
| 前进、后退、刷新、外部打开 | ArrowRight / ArrowLeft / RotateCw / ExternalLink |
| 附件、模型、权限、计划 | Paperclip / Sparkles / ShieldCheck / ListTree |
| 发送、停止、完成、加载 | ArrowUp / Square / CircleCheck / LoaderCircle |

数字、加减差异、键盘快捷键和 Git 的 M/A/D 是内容文本，不用图标替换；禁止的是把 ×、↻、⛶、▸ 等字符当操作图标。

## 插件内部实现顺序

1. **基础层。** 新建插件内 tokens、Icon、IconButton、Button、Menu/Popover、Dialog、Tabs、Status、EmptyState。所有样式限定在插件根或插件 portal 容器内，避免影响 DSH 外壳。将现有局部组件逐步迁移，共存阶段也通过同一 token 取值。
2. **页面外框。** 改造 FocusSidebar、ThreadView、ThreadActions 与 ConsolePage。项目导航建议宽 224–240px，右栏保留拖动宽度，聊天不足舒适阅读宽度时优先收起辅助区域；不在 1024px 下强制维持三块窄栏。
3. **对话和输入。** 统一 Markdown、工具聚合、代码、文件变更、审批、草稿、附件、斜杠命令、模型和权限。保留发送、停止、steer、计划模式与草稿持久化逻辑。额度和 daemon 等维护信息移到低频入口。
4. **工作区。** 在 src/client/sidebar 和插件持有的 vendor/dsh-dockkit 适配层改图标与外观，沿用现有布局引擎；标签、拖动占位、分割线、菜单、全屏、浮动窗口共同调整。FilesPane、DocumentPane、GitTab、TerminalTab 和 BrowserPane 使用相同工具栏与状态组件。
5. **弹窗和主题。** 项目/目录、版本与健康、重命名、删除确认、完整访问确认和错误反馈统一。长路径可复制，错误摘要与技术详情分层；不改变任何授权范围。
6. **响应式和清理。** 桌面与手机分别验收，再移除被替代的 Glyph 和旧样式。右栏布局序列化版本只有在数据结构确实变化时才升级；单纯换视觉不重置用户布局。

## 如何使用 DSH 热加载验收

本轮截图实例已在同版本隔离 DSH 中打开真实插件。后续改造保持不改 DSH：

1. 运行项目现有 build，确认插件 client.js 是本次产物。
2. 使用隔离 DSH_HOME；hmr 配置的 base 指向本仓库，root 包含 index.js、lib；按照 scripts/reload-host.mjs 现有流程触发插件重载。不要把修改 DSH 包代码当作加载方案。
3. 先建立真实用户状态：有草稿、有附件、选中文件、两个分栏、浮动标签、浏览器地址；记录状态快照。
4. 替换前端产物并等待 HMR 完成，在同一浏览器页面验收新样式和交互。确认 React 根和样式没有重复、监听器/轮询没有翻倍，草稿、工作区路径、当前会话与布局保留。
5. 如果涉及后端 RPC，再触发 host reload；确认 SSE 自动重连、文件 watcher 重建，旧 watcher 关闭，审批状态恢复，重复打开与关闭工具不泄漏资源。
6. 保留重载前后截图、控制台错误、接口结果和 HMR 日志作为验收证据。此前的 HMR 测试记录可参考 docs/RIGHTBAR_ACCEPTANCE.md，本次新视觉必须重新加载验收。

## 正式版的验证矩阵

- 尺寸：1440×1000、1280×900、1024×900、768×1024、390×844、375×812；验明暗主题、200% 缩放和面板拖宽/缩窄。
- 对话：空会话、短回复、长 Markdown、长代码与表格、思考/工具状态、流式输出、停止、失败、审批、多轮滚动、切会话草稿。
- 输入：模型、推理强度、权限、完整访问确认、计划模式、中文输入法、附件长名、上传中/失败、斜杠搜索、键盘选择。
- 工作区：嵌套目录、长文件名、无文件、Markdown/源码、二进制与截断提示；Git 无改动/未初始化/未首提/错误/大 diff；终端执行中/退出/失败；浏览器空态/无效地址/嵌入失败。
- Dock：多标签、拖序、跨分栏、关闭活动标签、全屏/恢复、浮动/停靠、刷新恢复、桌面布局切到手机再返回。
- 无障碍：键盘操作、焦点可见、弹窗焦点限制与恢复、Escape 分层、tab aria-selected、图标按钮有名称、状态文本和颜色同时存在。
- 自动化：运行已有适用测试与构建；为主题/布局持久化、关键交互回归增加必要测试。截图比较覆盖代表状态，不给每个颜色写镜像单元测试。
- 完成标准：所有现有入口仍可达；手机无横向溢出和不可读多栏；无字符操作图标；无未处理 pageerror；DSH HMR 后状态保持；无 DSH 源码改动。
